**핵심 발견 1 — Pretendard 한글 = Noto 한글 × (1.982, 1.965), 1770 셀 중앙 정렬, y −10.**
124 음절 표본 중앙값: 가로비 1.9822(Q1–Q3 1.9802–1.9836), 세로비 1.9648(1.9639–1.9658), 진행폭비 1.9239 = 1770/920. 검증(400): 가 x 55.2→82.7(실제 84), 889.5→1736.3(1736); y −77.1→−161.5(−162), 827.3→1615.6(1616). ㄱ·ㅏ 도 ±2 unit. 웨이트 100/700/900 에서도 1.986/1.981/1.988 · 1.969/1.963/1.968 로 ±0.003 이내 → **상수로 고정**.
> 팀장 표본값 2.052/2.014 는 Noto VF 의 **기본 인스턴스(wght 100, Thin)** bbox 와 Pretendard Regular 를 비교한 것이다(Thin 은 획이 가늘어 bbox 가 작음). 같은 굵기끼리 비교하면 1.98/1.965 이며, 리서치의 1.966(=2.048×0.96)은 세로비에 정확히 해당한다. 가로가 0.9% 더 큰 것은 Pretendard 가 실제로 x 0.968·y 0.960 으로 비균등 축소한 결과이므로 **그대로 따른다**(균등 1.97 로 하면 기존 한글 대비 가로 0.5% 좁아져 자모·음절 나란히 놓였을 때 폭이 미세하게 어긋남).

> 교차검증: 빌더의 `build/supplement-measure.md`(웨이트 일치 인스턴스, Regular/Bold 표본 39쌍)와 일치 — 가 1.981/1.967, ㄱ 1.982/1.962, ① 1.693/1.695, ○ 1.753/1.756, ◇ 1.949/1.947, ㈜ 2.090/2.108, ※ 1.481/1.478, ★ 1.985/1.975 (본 문서 §4 표는 표본을 카테고리당 20~124 로 늘린 중앙값).

**핵심 발견 2 — 기호는 카테고리(정확히는 Pretendard 의 동종 참조 글립)마다 비율이 다르다.** ① 1.696 · ㈜ 2.107 · ■ 1.792 · ○ 1.756 · ◇ 1.947 · △ 1.889 · ★ 1.975 · ※ 1.478 · ≠ 1.475 · ∫ 2.080 · 단위 ㎏ 1.860(세로) · 전각 1.92(셀). Pretendard 의 기호는 Inter 유래(라틴 비례폭)라 Noto 의 전각 기호와 구조가 달라, **단일 스케일은 불가**하고 "참조쌍 변환"(§3)으로 동종 기호에 맞춘다.

**핵심 발견 3 — Pretendard 의 참조 기호 크기·진행폭은 웨이트에 따라 변한다**(① adv 1752/1784/1832/1865, 세로비 1.645/1.696/1.743/1.776 @100/400/700/900; ㈜ adv 2153/2320/2442/2524). 따라서 참조쌍 변환은 **인스턴스(웨이트)마다 다시 계산**한다. 한글류(상수)·괘선(상수)만 예외.

## 3. 변환 모델 (빌더 구현 규칙)

세 가지 모드만 쓴다. 좌표는 Noto 인스턴스 글립의 좌표(UPM 1000)를 입력으로 받아 Pretendard 좌표(UPM 2048)를 낸다.

| 모드 | 정의 | 진행폭 |
|---|---|---|
| **fixed** (한글류) | `x' = sx·(x − N.adv/2) + P.adv/2`, `y' = sy·y + dy` — sx 1.982, sy 1.965, dy −10 | `P.adv = round(N.adv × 1.9239)` (920→1770, 250→481) |
| **ref** (참조쌍) | 같은 웨이트의 참조 글립 R 이 두 폰트에 다 있을 때: `s = P_R.h / N_R.h`(균등; 화살표만 `P_R.w / N_R.w`), `x' = s·(x − cxN) + cxP`, `y' = s·(y − cyN) + cyP` (c = R 의 bbox 중심) | `adv=ref`: `P_R.adv` 그대로(정형 셀) / `adv=fit`: `round(w' + 2·sb)` 후 bbox 를 진행폭 중앙에 재배치(비례 셀) |
| **ref-baseline** (문자형 수학기호) | ref 와 같되 y 는 `y' = s·y`(베이스라인 고정, 중심 정렬 안 함) | fit |
| **affine** (괘선·블록·반각) | 명시 상수 `x' = sx·x + tx`, `y' = sy·y + ty` | 명시 |
| **composite / mirror** | §5 | §5 |

- 변환 후 좌표는 정수로 반올림(TrueType). 윤곽 방향은 유지(mirror 만 반전 후 `ReverseContourPen` 으로 방향 복원).
- `ref` 의 P_R 은 해당 웨이트의 정적 TTF(9종은 Pretendard zip `public/static/alternative/` 에서 추출)에서, N_R 은 `varLib.instancer` 로 같은 wght 를 뽑은 Noto 에서 읽는다. 참조값은 빌드 시 자동 계산하고 `build/supplement-refs-<W>.json` 에 남긴다(아래 표는 400·700 검증값).

## 7. 변수 폰트 이식 (AGENTS §8: 9 인스턴스 피크 gvar)

1. **마스터 = 9 인스턴스 산출물**: 정적 빌드에서 만든 9 웨이트의 보충 글립 외곽선(§4 규칙을 웨이트마다 적용한 결과)을 그대로 마스터로 쓴다. 이 글립들은 같은 Noto 글립의 아핀 변환이므로 점 수·윤곽·on/off 패턴이 9개 모두 동일하다(실측: 904글립 100/400/900 불일치 0). 합성 3자는 부품이 웨이트마다 같은 구조(equal 8점·period 16점·◇ 8점·◆ 4점)라 동일. ⅔ 컴포지트는 부품 gvar 가 이미 있으므로 컴포넌트 오프셋 델타만 추가.
2. **축 범위 — 확정(AGENTS §8 2026-09-06): Pretendard VF 축 wght 45–930 을 100–900 으로 자른다**(`instancer.instantiateVariableFont(vf, {"wght": (100, 900)})`, L4 부분 인스턴싱). 정규화 좌표가 100→−1.0, 200→−0.667, 300→−0.333, 400→0, 500→0.2, 600→0.4, 700→0.6, 800→0.8, 900→1.0 이 되어 9 피크가 축 끝을 정확히 덮는다(정적 9종과 범위 일치, STAT 값이 축 전체를 덮음; 45–100 헤어라인은 포기). 45–930 을 유지했다면 100→−0.845, 900→+0.943 이라 [−1, −0.845]·[0.943, 1] 구간에서 델타가 0 으로 되돌아가 −1.0/+1.0 에 복제 tuple 2개가 더 필요했을 것(기각).
3. **tuple(텐트)**: 기본(400)을 제외한 8 피크 각각 `(prev, peak, next)` = 이웃 피크로 감싼 텐트 → 두 이웃 사이에서 정확히 선형 보간(스칼라 합 1). 예: 300 → (−0.667, −0.333, 0), 500 → (0, 0.2, 0.4), 900 → (0.8, 1.0, 1.0).

5. 구현: 9 마스터(인스턴스) 외곽선에서 기본(400) 대비 델타를 계산해 **gvar `TupleVariation` 을 직접 생성**하고 `glyf/gvar/hmtx/cmap` 에 추가한다 — 보충 글립만 담은 mini-VF 를 `fontTools.varLib.build` 로 만들어 병합하는 방식과 **동등**(축 정규화가 같으므로 결과 tuple 이 같다). 빌더는 직접 생성 방식으로 구현했다(2026-09-06).
6. 괘선·블록은 웨이트 불변 → 델타 전부 0(tuple 생략 가능).
7. **중첩 컴포지트 평탄화(8차 빌드 도입)**: 컴포지트가 다른 컴포지트를 참조하면(fontbakery `nested_components`) `outer∘inner` 변환을 합성해 **한 단계 컴포지트로 평탄화**한다. 외곽선은 바뀌지 않으므로 bbox 비교로 증명한다. 정적은 서브셋 후(웨이트당 106글립, bbox 불일치 0), VF 는 9 인스턴스에서 전개한 오프셋으로 gvar 를 재생성한다(8차: 중첩 167 → 0). **채택 판정 허용치는 글립 성격으로 나눈다** — Noto 유래 보충 글립 ≤ 2 unit, Pretendard 유래 합성·컴포지트 ≤ 8 unit(아래 (c)). 이 구분 없이 일괄 2 unit 을 쓰면 Pretendard VF 보간과 정적 TTF 의 반올림 차(2.0~2.4 unit)로 평탄화가 되돌려져 중첩이 잔존한다(6차 사례 5글립).

- (c) 빌드된 VF 를 100…900 으로 인스턴스화해 정적 9종과 비교: **Noto 유래** 보충 글립 904 는 좌표 최대 차 ≤ **2 unit**, **합성·컴포지트 8자**(⅔ U+2154 · ∼ U+223C · ≒ U+2252 · ◈ U+25C8 · ￢ U+FFE2 · ￣ U+FFE3 · ￤ U+FFE4 · **Ǆ U+01C4**)는 ≤ **8 unit**(부품 오프셋·미러·분해·평탄화의 반올림 누적 허용), 진행폭은 Noto 유래 글립은 동일·컴포지트 8자는 ≤ 8 unit, cmap 동일.
  - Ǆ(U+01C4)는 6차 빌드에서 QA 티켓 1(case_mapping) 대응으로 추가한 `D`+`Z`+`caron` 컴포지트다(`config.SUPPLEMENT_COMPOSITE_PATCHES`). 부품이 **Pretendard 글립**이라 VF(=Pretendard VF 보간)와 정적(=Pretendard 정적 TTF) 사이에 반올림 차가 생기는 기존 7자와 **같은 부류**이며, 실측 편차는 기존보다 작다(VF↔정적 adv 1~2 unit·bbox ≤1.2 unit; 비교: ⅔ adv 3 unit·≒ bbox 3 unit). 이 8자를 "Noto 유래 ≤2 unit" 기준으로 재면 오탐 FAIL 이 난다(티켓 7).
  - 같은 이유로 **평탄화된 Pretendard 유래 컴포지트**(§7-7, 아래 QA (e))도 컴포지트 허용치 8 unit 을 쓴다(8차 실측 최대 bbox 4.804·adv 4 unit).
- (d) 축 중간값(예: 250, 650)에서 괘선 연결(§4-5 (b)(c)) 유지.
- (e) **중첩 컴포지트 0**: VF·정적 모두 컴포지트가 컴포지트를 참조하지 않는다(fontbakery `nested_components`). 평탄화는 `outer∘inner` 변환 합성이라 외곽선이 바뀌지 않으며 bbox 로 증명한다(8차 실측: 중첩 167 → 0, 정적 대비 최대 4.804 unit).
- (f) **고아 글립 0**: cmap(UVS 포함)·GSUB/GPOS/GDEF 트리·컴포넌트 폐포·예약 글립(`.notdef` `.null` `nonmarkingreturn` `CR`) 어디에서도 참조되지 않는 글립이 없다(fontbakery `unreachable_glyphs`, `04-features.md` §2 와 정합).
- (g) 8차 빌드 실측 기준값: 정적 9종·VF 모두 **글립 13,980 · cmap 13,254**.
